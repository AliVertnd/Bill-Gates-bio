## 4. Помощь по самым насущным вопросам

### 4.1. Обещание 30 / 60 / 90 (вопрос 6)

Практика retainers: первые 90 дней решают удержание; обещание должно быть **наблюдаемым результатом**, не «мы подумаем о развитии».

Привязка к вашему описанию (встраиваемся → находим рост/риски → реализуем вместе):

| Срок | Обещание (черновик для утверждения) | Что клиент получает на руки |
|------|--------------------------------------|-----------------------------|
| **30 дней** | Общая карта контуров маркетинга и IT и связанных процессов: где рост, где риски, где разрывы между отделами | Документ «единое видение на 90 дней» + приоритизированный backlog блокеров, согласованный с ЛПР |
| **60 дней** | Сняты или поставлены под контроль **1–3 главных блокера** (подрядчики / аналитика / воронка / ключевой IT-разрыв — по факту аудита); стратегия скорректирована под текущие внешние условия | Статус блокеров, обновлённый план, видимый прогресс в контуре |
| **90 дней** | Запущены **1–2 приоритетных инициативы развития** из согласованного backlog (не «все идеи», а выбранные мощные); есть ритм управления контуром | Работающие инициативы + отчёт «что изменилось в контуре» + план следующего квартала |

**Правило формулировок:** говорим «карта / контроль блокеров / запуск инициатив», не «полноценное улучшение всего бизнеса за квартал».

---

### 4.2. Что такое «триггеры» (вопрос 12)

Триггер — событие, после которого компания **начинает искать** таких как вы.

Черновик триггеров под Impro.group (выберите 5–7 «наших»):

1. Выход девелопера / бренда в **новый регион** или запуск нового объекта/линейки  
2. **Хаос подрядчиков** (много чатов, нет единого контроля маркетинга/IT)  
3. Уход **ключевого** маркетолога / IT-руководителя / продакта  
4. Новый **CMO / коммерческий / IT-директор** (первые 90 дней в роли)  
5. Слив **маркетингового или IT-бюджета** без понятного результата  
6. Нужна **сквозная связка** маркетинг–продажи–IT, а внутри не тянут  
7. Давление собственника: «почему не растём / не управляем»  
8. Старт тендера / федеральной программы / крупного подрядного контура

### 4.3. Акцент сайта (вопрос 20)

Исходя из ваших акцентов (30% риски/стабильность) + отличия «в контуре» + тезиса про рост/риски:

**Рекомендация:** главный акцент страницы —  
> **Единый контур маркетинга и IT внутри компании: рост и контроль рисков, а не ещё один подряд.**

«Быстрые едят больших» — сильный слоган второго плана / контент / холодка, не единственный H1 (иначе звучите как growth-хакеры, а не контурный партнёр).

---

### 4.4. Вход vs сразу ретейнер (вопрос 21)

На рынке для high-ticket retainers нормальна связка:

```text
Низкий барьер входа (знакомство → платный/зачётный разбор)
  → короткий пилот 30–90 дней
  → ретейнер контура
```

Прямая продажа «сразу 600к/мес» бьёт конверсию у незнакомых.  
Прямая продажа только мелкого входа без пути в ретейнер бьёт LTV.

**Рекомендация модели:**
1. Созвон-знакомство (бесплатно, короткий fit)  
2. Платный вход 80–150к = диагностика контура (с зачётом в первый месяц ретейнера, если заходят)  
3. Пилот / ретейнер от 600к  

Так конверсия входа выше, а экономика целится в ретейнер. Чек 80к как раз логичен как **пакет диагностики контура**, не как «ещё один мелкий сайт».

---

### 4.5. Оффер холодки (вопрос 18) — каркас, не финальный текст

Цель первого касания: **созвон-знакомство**, не продажа 600к.

Каркас сообщения:
1. Наблюдение по компании (регион / подрядчики / сайт / вакансия / запуск)  
2. Гипотеза риска или точки роста в маркетинге/IT-контуре  
3. Предложение: 20–30 мин разобрать, есть ли смысл в более глубоком разборе  
4. Второй шаг после fit: короткий первичный аудит → второй созвон с выводами  

Точный текст — после 1 отрасли-фокуса на холодку (девелопмент как сильный пример).

## 6. Красные флаги (проверить честно)

1. «Кейсами доказано всё» без 3 публичных историй — для рынка = пусто.  
2. **25–35 ретейнеров × 600к** при штате 6–10 = либо мощный подрядный контур, либо завышенный потолок; развести «через год» vs «через 24–36 мес».  
3. Холодка 40% без оффера = главный операционный риск плана.  
4. Найм «зависит от услуг» при том что услуги ещё не зафиксированы — блокер стратегии; услуги надо поднимать следующим блоком параллельно.
