## 1. Суть подхода (ваша логика → система)

```text
МИКРОУСЛУГА          → атом с базовой стоимостью и правилами применения
       ↓
УСЛУГА / СВЯЗКА      → набор микроуслуг (например «SEO-ведение»)
       ↓
КОЭФФИЦИЕНТЫ КЛИЕНТА → умножают связку (сложность, отрасль, срочность, объём…)
       ↓
ОФФЕР / ПАКЕТ        → то, что видит клиент (вход 80к, ретейнер контура…)
       ↓
КАЛЬКУЛЯТОР          → собирает строки → считает итог → выводит в языке позиции
```

**Не делаем:** прайс «SEO от 80к» без состава.  
**Делаем:** SEO = аналитика + семантика + ТЗ + тексты + техника + отчётность + …; каждая строка описана; связка собирается; к связке — коэффициенты заказчика.

Это совпадает с рынком 2025–26: productized services (атомы + пакеты), а для mid-market РФ — гибрид «меню атомов → собранный контур», а не бесконечное custom КП с нуля.

## 2. Три уровня каталога

| Уровень | Что это | Пример | Для кого виден |
|---------|---------|--------|----------------|
| **L0 Микроуслуга** | Атом работы | SEO: сбор семантики; SEO: ежемес. отчёт; CRM: настройка этапов | Внутр. + калькулятор |
| **L1 Услуга** | Связка атомов под задачу | «SEO-ведение / мес», «Диагностика контура» | Прайс / КП |
| **L2 Контур / ретейнер** | Несколько L1 под позицию компании | «Ретейнер маркетингово–IT-контура» | Главный оффер |

Позиция Impro.group живёт на **L2**. L0/L1 — чтобы не врать в составе и считать маржу.

## 3. Карточка микроуслуги (обязательные поля)

Без этих полей калькулятор потом не собрать.

| Поле | Зачем |
|------|--------|
| `id` | Стабильный код (напр. `seo.semantic.v1`) |
| `название` | Коротко |
| `линейка` | Диагностика / SEO / Performance / Разработка / … |
| `входит_в_L1` | В какие услуги-связки входит |
| `когда_применяется` | Триггер: «новый сайт», «падение трафика», «нет сквозной аналитики»… |
| `кому_нужна` | Тип клиента / роль ЛПР / стадия |
| `боль` | Какую боль закрывает (язык клиента) |
| `результат` | Артефакт / исход |
| `что_входит` | Scope |
| `что_не_входит` | Граница |
| `формат` | разово / мес / спринт |
| `базовые_часы` | Норматив |
| `базовая_стоимость_₽` | Floor до коэффициентов клиента |
| `роль` | Кто делает (мы / подряд) |
| `зависимость` | Какие микроуслуги должны быть до/вместе |
| `можно_одну` | Да/нет — продаём ли атомом или только в связке |
| `связь_с_позицией` | Как это усиливает «контур», а не «ещё подряд» |
| `статус` | сейчас умеем / через подряд / позже |

Полный шаблон строки: [`reestr-mikroservices.md`](reestr-mikroservices.md)  
Модель коэффициентов: [`model-ceny-i-koefficienty.md`](model-ceny-i-koefficienty.md)

## 4. Как действуем (порядок работ)

### Этап A — Метод и поля *(сегодня)*
1. Утверждаем эту логику + поля карточки + формулу коэффициентов.  
2. Research рынка (тренды, потребности mid-market, ценовые вилки) — [`../research/blok-08/`](../research/blok-08/).  
3. Короткий вопросник основателям — что уже умеем / чего нет / какие отрасли.

### Этап B — Сбор полного списка микроуслуг
1. Идём **линейка за линейкой** (не всё сразу в один день).  
2. На каждую линейку: рынок → черновой список атомов → ваши «да/нет/править/цена».  
3. Стартовые линейки (предложение):  
   - Диагностика и карта контура  
   - Стратегия / выбор направлений роста и рисков  
   - Маркетинг-контур (performance, воронка, CRM-маркетинг)  
   - SEO (как эталон декомпозиции)  
   - Разработка и продукт  
   - Автоматизация / интеграции / данные  
   - Контент / медиа  
   - PMO подрядчиков  
   - Ретейнер контура (сборка L1)

### Этап C — Связки L1 и офферы L2
1. Собираем типовые пакеты: вход ≥80к, проектные связки, ретейнер ~600к.  
2. Каждая связка = список `id` микроуслуг + какие коэффициенты по умолчанию.

### Этап D — Калькулятор
1. Таблица: выбрать атомы → сумма баз → × коэффициенты клиента → итог.  
2. Вывод в языке позиции (не «80 часов SEO», а «контур: поисковый канал + аналитика + отчётность в единой точке»).

## 5. Связь с позицией компании

Любая микроуслуга, которую продаём **в одиночку ниже порога / без связки контура**, — риск скатиться в красный океан (агентство/студия).

Правила витрины:

| Можно | Нельзя на старте |
|-------|------------------|
| Атом внутри диагностики / ретейнера / проекта контура | Дешёвое SEO «в вакууме» как ядро |
| Отдельный атом, если это вход в контур (с зачётом) | Часы без ответственности за связку |
| Подряд под нашим PMO | Отдать клиента подрядчику без нашей точки |
