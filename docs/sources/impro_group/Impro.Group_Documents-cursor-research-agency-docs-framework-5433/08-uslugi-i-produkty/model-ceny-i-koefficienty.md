# Модель цены и коэффициенты клиента

> Дата: 2026-07-27  
> Статус: **черновик метода** (цифры коэффициентов — гипотезы до калибровки)  
> Каталог атомов: [`reestr-mikroservices.md`](reestr-mikroservices.md)

---

## 1. Формула

```text
Цена_оффера =
  Σ ( базовая_стоимость_микроуслуги_i × k_формат_i )
  × K_клиента
  × K_срочность
  + внешние_расходы_подрядчиков_без_нашей_маржи   # mediabudget, лицензии — отдельно
  + наценка_PMO_контура                            # если держим связку
```

Где:

| Символ | Смысл |
|--------|--------|
| `базовая_стоимость` | Floor атома при «нормальном» mid-market клиенте (5–10 млн ₽/мес), без срочности |
| `k_формат` | 1.0 разово; для абонентки — доля месяца / частота |
| `K_клиента` | Произведение коэффициентов профиля заказчика |
| `K_срочность` | 1.0 обычный срок; 1.25–1.5 сжатый |
| `наценка_PMO` | Плата за «одну точку» и управление подрядчиками (суть позиции) |

**Медиабюджет, лицензии CRM, хостинг** — всегда отдельной строкой, не внутри маржи услуги.

## 2. Коэффициенты клиента `K_клиента`

Считаем как произведение (можно заменить на сумму надбавок — решим после калибровки).

| Код | Ось | 0.9 | 1.0 (база) | 1.2 | 1.4–1.6 |
|-----|-----|-----|------------|-----|---------|
| `K_masshtab` | Масштаб (сайты, регионы, SKU, объекты) | малый контур | 1 бренд / 1 сайт | 2–3 контура | сеть / мультирегион |
| `K_zrelost` | Зрелость данных и доступов | всё готово | частично | хаос, нет доступов | нет аналитики + сопротивление |
| `K_otrasl` | Отрасль / регуляторика | простая B2B | типовой mid-market | девелопмент / сложные продажи | фин/мед/гос-смежно |
| `K_stakeholder` | Число ЛПР и согласований | 1 ЛПР | 2 | комитет | холдинг |
| `K_teh_dolg` | Техдолг IT/маркетинг | чистый контур | средний | тяжёлый legacy | «всё переписать» |
| `K_podryad` | Доля внешних подрядчиков под нами | 0 | 1–2 | 3–5 | рой |

**Правило пола:** итог после коэффициентов не ниже **минимального чека** компании (сейчас ориентир 80к на входной платный шаг; для ретейнера — экономика ~600к ядра).

## 3. Как калькулятор будет собирать (логика UI позже)

```text
1. Выбрать профиль клиента → автоматически K_клиента
2. Выбрать цель / триггер («упал трафик», «нет связки CRM», «нужен контур»)
3. Калькулятор предлагает набор микроуслуг (когда_применяется ∩ кому_нужна)
4. Можно снять/добавить атомы вручную
5. Собрать в L1 или L2 (ретейнер)
6. Показать:
   - состав (язык клиента + связь с контуром)
   - базу
   - коэффициенты
   - итог
   - что не входит
```

## 4. Откуда берём базовые цены атомов

Приоритет источников (пока плаваете в рынке — так и закрываем дыру):

1. **Рыночные вилки РФ 2025–26** (SEO, performance, стратегия, разработка) — research  
2. **Ваш норматив часов × внутренняя ставка** (когда появится)  
3. **Себестоимость подряда + наша наценка PMO**  
4. Калибровка: «за эту связку клиент mid-market платит / не платит»

Базовые цены в реестре на старте = **гипотезы рынка**, помечены `гипотеза` / `калибровать`.

## 5. Пример (схема, не финальные цифры)

**Связка L1 «SEO-ведение / мес»** = атомы:  
мониторинг позиций + контент-ТЗ×N + техправки + ссылочный контур (если нужен) + отчёт + статус-созвон.

База атомов (условно) 95к.  
Клиент: девелопер, 2 ЖК, слабая аналитика → `K_otrasl 1.2 × K_masshtab 1.2 × K_zrelost 1.2 ≈ 1.73`.  
Итог ≈ 95к × 1.73 ≈ **164к/мес** только SEO-слой.  
В ретейнере контура SEO — одна из строк рядом с CRM/PMO/стратегией, не отдельная витрина «мы SEO-агентство».
