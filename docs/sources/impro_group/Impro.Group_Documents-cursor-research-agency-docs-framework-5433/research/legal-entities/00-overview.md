# Юрлица и compliance для Impro.group (РФ)

> Research note · 2026-07-22  
> **Не является юридической или налоговой консультацией.** Перед решениями — юрист + бухгалтер.

## 1. Варианты юрмодели

### Вариант A — одно ООО «Impro.group»

**Когда:** старт/рост, партнёры, B2B, команда, без жёсткой цели IT-аккредитации.

Плюсы:
- проще учёт и управление
- удобно для клиентов и тендеров
- можно оформить доли и корпоративный договор

Минусы:
- смешение marketing + IT выручки мешает аккредитации/льготам
- общие риски по всем направлениям

### Вариант B — два ООО

Пример:
- ООО «Импро Групп» — маркетинг, креатив, стратегия, консалтинг
- ООО «Импро Тех» — разработка, интеграции, ПО, поддержка → кандидат на Минцифры

Плюсы:
- чистая IT-выручка
- разные договорные шаблоны и риски
- проще готовить аккредитацию

Минусы:
- двойная бухгалтерия
- договоры между связанными лицами
- нельзя «дробить» бизнес только ради налоговой выгоды

### Вариант C — группа / холдинг

Когда есть разные партнёры, продукты, M&A, международка.

### Вариант D — ООО + ИП / самозанятые

Гибкий production-контур. Риски переквалификации в трудовые отношения, особенно при:
- бывших сотрудниках < 2 лет (для НПД)
- регулярных фиксированных выплатах
- подчинении ПВТР / полной занятости одному заказчику

## 2. IT-аккредитация Минцифры (если цель есть)

Ключевые ориентиры (проверять по актуальной редакции ПП №1729):

- профильный ОКВЭД
- доля IT-выручки (для аккредитации ориентир >30%; для налоговых льгот критерии жёстче)
- требования к сайту (реквизиты, описание IT-деятельности/продуктов)
- согласие на раскрытие налоговой тайны
- ежегодное подтверждение через Госуслуги

Практический вывод для Impro:  
если аккредитация в планах — **не смешивать** рекламную/маркетинговую выручку с IT в одном контуре учёта.

## 3. Корпоративный пакет документов

Минимум:
- Устав
- Решение / протокол создания
- Список участников
- Корпоративный договор (ст. 67.2 ГК РФ)
- Протоколы собраний
- Приказ о назначении директора
- Регламент управленческих решений / Совета
- Политика конфликта интересов

## 4. HR / ЛНА (если есть работники)

Минимум:
- Штатное расписание
- Трудовые договоры
- ПВТР
- Положение об оплате труда / премировании
- Положение о ПДн работников
- График отпусков, табель
- Role cards / должностные инструкции
- NDA + соглашение о служебных РИД
- Политика удалёнки / доступов

## 5. Клиентский договорной стек (РФ-адаптация MSA+SOW)

| Документ | Зачем |
|----------|-------|
| NDA | До обмена чувствительной информацией |
| Договор оказания услуг (рамочный) | Общие условия, IP, ответственность, расторжение |
| Приложение / SOW / ТЗ | Scope, сроки, стоимость, acceptance |
| Акт | Закрытие этапа / проекта |
| Change request / доп. соглашение | Изменение объёма |
| SLA | Поддержка / retainer |
| Соглашение по ПДн (поручение) | Если обрабатываете ПДн клиента |
| Договор с подрядчиком + IP assignment | Downstream защита |

Критичные клаузы:
- переход прав на РИД (когда именно — после оплаты / акта)
- reusable IP / методологии остаются у Impro
- limitation of liability
- порядок правок и согласований
- доступы к кабинетам, репозиториям, аналитике

## 6. 152-ФЗ / сайт

Минимум для сайта и операций:
- Политика обработки ПДн
- Согласия под формами
- Cookie / Метрика notice
- Внутреннее положение по ПДн
- Ответственный за ПДн
- Реестр процессов обработки
- Договоры поручения с подрядчиками (CRM, email, хостинг)

## 7. Рекомендация для Impro.group на текущем этапе

1. Зафиксировать текущие юрлица и доли (вопросы B в founders-intake)
2. Управленчески вести P&L по практикам уже сейчас
3. Юридически:
   - если IT-аккредитация **не** цель → одно ООО + сильный договорной стек
   - если цель есть → проектировать Agency + Tech
4. Параллельно собрать MVP шаблоны: договор, SOW, NDA, акт, change request, contractor+IP
5. Не строить холдинг «на вырост» без конкретной причины
